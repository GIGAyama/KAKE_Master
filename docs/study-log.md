# 学習ログ(study.v1)— 九九カードの実装

**対象** 九九カード(`https://kake-master.giga-school.com/`)
**出力スキーマ** `study.v1`
**共通モジュール版** `studyLog.js` ロジック版 1.1
**アプリ版** `1.4.0`(`js/studySession.js` の `APP_VERSION`。`sw.js` の `VERSION` も同じ値に合わせる)

このアプリは「学習ログ共通スキーマ仕様書 `study.v1`(1.5)」に準拠し、
学習の記録を端末の `localStorage` に保存する。**外部への送信は一切行わない。**
氏名・出席番号などの識別情報も持たない(識別子は送信ページが付与する)。

---

## 1. ファイル構成(3層)

| ファイル | 役割 | 変更してよいか |
|---|---|---|
| `js/studyLog.js` | 共通の保存処理(`saveStudyRecord`) | **不可**。全アプリ共通・同一ロジック |
| `js/studySession.js` | 九九カード固有のレコード組み立て・中断検知 | このアプリの都合で変更してよい |
| `js/studyStats.js` | 読み出しと集計(きろく画面の表示用) | 同上。**読み出し専用** |

保存キーは全アプリ共通の **`study.records.v1`**。
ただし **キーが共通なだけで、保存先はアプリごとに別々になった**（下の §12）。
このアプリ固有のデータ(`kuku-card-v1`)とは別枠であり、
「きろくをぜんぶけす」でも `study.records.v1` は削除しない(§1.2)。

## 3. モード別の割り当て

| 画面 | `mode` | `unit.id` | `source` | `grading` | `multiplayer` | `items` |
|---|---|---|---|---|---|---|
| カードでれんしゅう(しき→こたえ) | `flashcard` | 段 | `course` | **`selfReport`** | `false` | マージ方式 |
| カードでれんしゅう(こたえ→しき) | `flashcard-reverse` | 段 | `course` | **`selfReport`** | `false` | マージ方式 |
| にがてカードのれんしゅう | `flashcard` | `weak-cards` | **`weak`** | `selfReport` | `false` | マージ方式 |
| こたえてクイズ | `quiz` | 段 | `course` | `objective` | `false` | 非マージ |
| ふたりでもんだい | `pair` | 段 | `course` | `selfReport` | **`true`** | なし |

`kind` は全モード `session`(開始から終了までが1レコード)。

### grading をモードで分ける理由

カードでれんしゅうは、児童が自分で「できた!」「もういちど」を選ぶ**自己評価**である。
数字で答えるクイズ(客観採点)と同じ正答率として扱ってはならない(§2.9)。
ふたりでもんだいは相手の児童が○×を押すため、同じく `selfReport` とし、
さらに `multiplayer: true` を立てて**学力指標から除外**する(§3.2 / §5.5)。

### 「こたえ → しき」を別モードにする理由

`6` を見て `2×3` を答える逆引きは、同じ児童でも正答率が変わる。
数値の意味を変える要因はフラグとして明示する(§0-4)ため、`mode` で分けている。

## 4. 単元ID(`unit`)

段そのものが難易度・範囲を表すため、段を単元とする(§2.5)。

| 選択 | `unit.id` | `unit.title` |
|---|---|---|
| 2のだんのみ | `dan-2` | `2のだん` |
| 2と3のだん | `mix-dan-2+dan-3` | `2・3のだん` |
| 4段以上 | `mix-dan-1+dan-2+dan-3+etc6` | `ぜんぶのだん` など |
| にがてカード | `weak-cards` | `にがてカード` |

- ID表(`STAGE_UNITS`)は**段の番号**を鍵にしている。表示名を直しても ID は変わらない
- 複数段を選んだときは、全段のIDを **`ext.unitIds`** に配列で残す(丸めた ID から復元できないため)
- `grade` は常に `2`(九九は2年の学習内容)、`preset` は常に `true`(児童作成の単元はない)

---

## 5. 設問層(`items`)

設問IDは式そのもの。`2×3` → **`2x3`**(半角 `x`。§2.10 の「式は20文字以内・日本語を含まない」に該当)。

| フィールド | 内容 |
|---|---|
| `q` | `2x3` |
| `ok` | 最終的に「できた!」/ 正解したか |
| `firstTry` | 1回目で「できた!」/ 正解したか |
| `tries` | 解答(判定)回数 |
| `ms` | そのカード・問題に かかった時間の合計 |
| `hint` | **こたえを見たか**(カードをめくってから判定した / クイズで誤答して正解を表示した) |
| `wrong` | クイズで入力した誤答(数字2桁まで) |

### カードでれんしゅうがマージ方式である理由

「もういちど」にしたカードは山の下にもどって再出題される。
同じカードは `q` をキーに1要素へ統合し、`tries` を重ね、
`firstTry` は初回の結果を保持、`ok` は最終結果で上書きする(§2.7)。
これにより `attempted === items.length` が常に成り立つ。

`summary.count` は**カードの種類数**で数える(のべ枚数ではない)。

### `hint` にこたえを見たかどうかを入れている理由

フラッシュカードは自己評価であり、「めくらずに できた」と「めくってから できた」では
定着の度合いが違う。`hint: false` の割合は自己評価の確からしさの目安になり、
教師が `selfReport` のデータをどこまで信じてよいかの判断材料になる。

### 200件の切り詰め

1レコードの最大出題数は 81(九九の総数)であり、`items` が200件を超えることはない。
それでも組み立て側で切り詰め・`ext.itemsTruncated` の退避処理を持たせてある(§2.7)。

---

## 6. `summary` の読み方

- **主指標は `firstTryCorrect`。**
- カードでれんしゅうは、全カードが「できた!」になるまで終わらないため、
  **`correct` は完走時に常に `count` と一致する**(けいさんカードと同じ構造)。横断比較には使えない
- 中断時は `attempted < count`。`count - attempted` が未着手の枚数
- ふたりでもんだいの `firstTryCorrect` は**2人の正解数の合計**。個人の学力ではない

---

## 7. `ext`

全モード共通:

```jsonc
{ "mastered": 42, "weakCards": 5, "streak": 3 }
```

| キー | 意味 |
|---|---|
| `mastered` | マスター済みの九九(81中)。連続3回正解で1つ |
| `weakCards` | にがてカードの枚数 |
| `streak` | 連続学習日数 |
| `unitIds` | 複数段を選んだときのみ。全段のID |

モード別の追加:

| モード | 追加キー |
|---|---|
| `flashcard` / `flashcard-reverse` | `order`(`asc`/`desc`/`random`)、`kana`、`wrongItems`(「もういちど」にした式・最大100) |
| `quiz` | `input`(`numpad`/`keyboard`/`mixed`)、`bestMs`、`isBest`、`wrongItems` |
| `pair` | `scores`(2人の得点)、`winner`(`1`/`2`/`null`) |

`ext.input` を残しているのは、ソフトウェアテンキーと物理キーボードでタイムが大きく変わり、
`elapsedMs` の比較が成立しなくなるため(100マス計算と同じ理由)。

## 8. 中断(`status: "aborted"`)

次の場合に中断として記録する(§5.4)。

| きっかけ | 動作 |
|---|---|
| 「やめる」ボタン・アプリ内の「もどる」・端末の「戻る」 | その時点で締める |
| タブが非表示のまま5分もどらない | **離脱した時刻**で締める(待機の5分は学習時間に含めない) |
| `pagehide`(タブ破棄・アプリ終了・画面遷移) | 必ず締める |

- **1問も解いていない中断は保存しない**(空レコードでログ枠500件を埋めないため)
- 中断したレコードには追記しない。復帰して学習が続く場合は、**残り分の枚数で新しいレコードを開始する**
- 復帰の検知は `visibilitychange` と `pageshow`(bfcache)。
  練習画面が表示されているときだけ再開し、結果画面やホームでは新しいレコードを作らない

Chromebook はメモリ不足やスリープでタブが破棄されるため、`beforeunload` ではなく
`pagehide` を使っている(`beforeunload` はモバイル・bfcache 経路で発火しないことがある)。

---

## 9. 学習時間

`elapsedMs`(開始から終了までの実時間)と `activeMs`(操作が続いていた時間)の両方を残す。
`activeMs` は仕様書 §2.8 の参照実装のまま(1秒刻みの加算、60秒無操作で停止、
`visibilitychange` 連動)。保存前に `Math.min(activeMs, elapsedMs)` でクランプする。
`timeBasis` は `"app"`。

---

## 10. 読み出し(きろく画面)

`js/studyStats.js` が `study.records.v1` を読み、きろく画面に
「がくしゅうの ふりかえり」(直近1週間のかいすう・学習時間・1回目でできた割合と、最近10回の一覧)を表示する。

- **読み出し専用。** 書き込み・削除は行わない
- `schema === 'study.v1'` かつ `appId === 'kuku-card'` のレコードだけを対象にする
- 正答率は `firstTryCorrect / attempted`
- **`multiplayer: true`(ふたりでもんだい)は正答率の計算から除外**し、取り組み量としてのみ数える
- パースに失敗しても空配列を返し、きろく画面の表示を壊さない

「きろくをぜんぶけす」は、このアプリ固有のデータ(`kuku-card-v1`)だけを消す。
共通の学習ログは残るため、リセット後もふりかえりの一覧は表示されたままになる。
これは仕様(§1.2)であり、不具合ではない。

---

## 11. 送信ページ側へのメモ

- `appId` は `kuku-card`
- `mode` は `flashcard` / `flashcard-reverse` / `quiz` / `pair`
- **`grading: "selfReport"` のレコード(カードでれんしゅう・ふたりでもんだい)を
  `objective`(クイズ)と同じ正答率として集計しないこと**
- **`multiplayer: true` のレコードは学力指標に使わないこと**
- `source: "weak"`(にがてカード)は母集団が偏るため、`course` と同じ土俵で比較しないこと

## 12. 独自ドメインへ移ったあとの「全アプリ共通」の意味

旧構成では、すべてのアプリが `gigayama.github.io` という**ひとつのオリジン**に
置かれていた。`localStorage` はオリジンごとに分かれるので、全アプリが
文字どおり同じ `study.records.v1` を読み書きしており、集計ページは
自分の `localStorage` を読むだけで横断集計ができていた。

独自ドメインに移り、アプリは `kake-master.giga-school.com` のように
**サブドメインごとに別のオリジン**になった。キー名は共通のままだが、
**中身は共有されない。** 集計ページから見えるのは自分のオリジンの分だけになる。

### 受け渡し口(`records-export.html`)

そこで、集計ページ側から取りに来てもらう形にした。

| ファイル | 役割 |
|---|---|
| `records-export.html` | 受け渡し口のページ。児童が開く画面ではない |
| `js/records-export.js` | `study.records.v1` を読んで `postMessage` で返す |

- 集計ページが**同一サイトの `iframe`** でこのページを開き、`postMessage` で問い合わせる
- サブドメイン同士は同一サイト(eTLD+1 が `giga-school.com`)なので、
  ブラウザの third-party ストレージ分割の対象にならず、`iframe` の中でも
  第一者と同じ `localStorage` が見える
- **読むだけ。書き込みも削除もしない。** 集計側の不具合でこのアプリの記録が
  壊れることが、原理的に起きないようにしてある
- 渡す相手は `giga-school.com` とそのサブドメインだけ。判定は
  `tests/records-export.test.mjs` で、通してはいけない例を並べて確かめている

### 旧アドレスの記録について

`gigayama.github.io` に保存されていた記録は、オリジンが変わったため
**引き継がれない。** 旧オリジンはホストごと転送されるようになっており、
そこで JavaScript を動かして読み出す手段がない。
